## 🔄 Реализация

### Свойства-обертки
```csharp
public Dictionary<int, int> InUseIn
{
    get => _packetDataService.InUseMapping[Models.PacketType.CS];
    set
    {
        _packetDataService.InUseMapping[Models.PacketType.CS].Clear();
        if (value != null)
        {
            foreach (var kvp in value)
            {
                _packetDataService.InUseMapping[Models.PacketType.CS][kvp.Key] = kvp.Value;
            }
            // Синхронизируем SC с теми же данными
            _packetDataService.InUseMapping[Models.PacketType.SC].Clear();
            foreach (var kvp in value)
            {
                _packetDataService.InUseMapping[Models.PacketType.SC][kvp.Key] = kvp.Value;
            }
        }
    }
}
```

### Маппинг
- `InUseIn` → `InUseMapping[PacketType.CS]` (с синхронизацией SC)
- `InUseOut` → `InUseMapping[PacketType.CS]` (с синхронизацией SC)
- **Примечание:** В будущем можно разделить InUseIn и InUseOut на отдельные свойства в PacketDataService

## 🔍 Особенности реализации

### Использование одного словаря для InUseIn и InUseOut
В текущей реализации и `InUseIn`, и `InUseOut` используют один и тот же словарь `InUseMapping[PacketType.CS]`. Это сделано для обратной совместимости, но в будущем можно разделить их на отдельные свойства в PacketDataService для большей ясности.

### Автоматическая синхронизация CS и SC
Поскольку в старом коде InUseIn/Out не разделялись по типам пакетов, а в PacketDataService они разделены, свойство-обертка автоматически синхронизирует SC данные с CS данными при установке значения. Это обеспечивает обратную совместимость и упрощает миграцию.
